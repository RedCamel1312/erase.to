# Implementation contract

This file records the interface shared by the server and clients. Public protocol documentation will supersede it before release.

## Layout and build

- `server/`: Rust 2024 / Axum / Tokio, standalone binary `erase-server`.
- `web/`: Svelte 5 + TypeScript, Vite static output `web/dist`.
- `shared/`: TypeScript cryptography, binary envelope and API types, shared by browser worker and CLI.
- `cli/`: TypeScript command line client. No server-side plaintext encryption.
- `deploy/`, `docs/`, `tests/`: deployment, specifications and integration tests.
- Root pnpm package owns dependencies and scripts. Rust has its own Cargo.lock.

## Protocol 1

Content is text or up to 8 files. Total input limit 64 MiB; text limit 8 MiB. File names, MIME types and content lengths are encrypted. No compression or previews.

Create packet: ASCII `ERS1`, 4-byte unsigned big-endian header length (1..2048), UTF-8 JSON header, ciphertext. Ciphertext length is 16 plus a positive multiple of 4096. Maximum packet size 64 MiB + 32768 bytes (67141632).

Header fields, in this serialization order:

`{version:1,id:string,ttl:number,views:number,peek:string,read:string,revoke:string,kdf:'none'|'argon2id',salt:string,nonce:string}`

- ID: 32 random bytes, canonical unpadded base64url (43 chars), generated by client.
- ttl: integer seconds, 60..604800. views: integer 1..100. Both limits always apply.
- peek/read/revoke: SHA-256 of respective 32-byte raw capabilities, lower-case hex (64 chars).
- nonce: 24 random bytes, base64url (32 chars).
- salt: empty for none; 16 random bytes base64url (22 chars) for Argon2id.
- Reject extra fields, missing fields, duplicates, noncanonical base64, malformed size, invalid ranges.
- The exact header bytes are XChaCha20-Poly1305 associated data. Server retains these exact bytes.
- Shared crypto module specifies inner binary encoding, key separation and fixed KDF parameters. KDF is Argon2id v1.3, 64 MiB, opslimit 3 (libsodium). No remote-supplied work factors.
- Random 256-bit master secret is retained in the fragment even with a passphrase. Peek derives from master only; read and encryption keys derive independently from master plus password-derived material. Revoke is an independent random 32-byte capability known only to sender.
- Metadata permits local comparison of the derived read hash, allowing incorrect passphrases to be rejected BEFORE any consuming request.

Share link: `/view#1.<id>.<master-secret-base64url>`. Receiver captures fragment and immediately replaces URL with `/view`. No identifiers in navigation paths, history state, storage or logs.

## HTTP

All JSON is strict; all API responses no-store. API accepts only same configured Origin, with absent Origin allowed for CLI (Sec-Fetch-Site must be absent or same-origin; cross-site and same-site rejected). All client calls send Origin including CLI. Config supports comma-separated PUBLIC_ORIGINS for HTTPS, onion and I2P origins. Host must match one configured origin. No proxy IP headers trusted or retained.

- GET `/api/config`: `{protocol:1,max_content_bytes:67108864,max_text_bytes:8388608,max_files:8,max_views:100,max_ttl:604800,pow_bits:18}`.
- GET `/api/challenge`: `{challenge:string,bits:18,expires_at:number}` (Unix seconds).
- POST `/api/notes`: body packet, `Content-Type: application/octet-stream`; `X-Erase-Challenge` and `X-Erase-Nonce` headers. Nonce decimal string 0..2^53-1. PoW SHA256(UTF8(challenge + '.' + lowerhex(SHA256(packet)) + '.' + nonce)) has first `bits` zero bits. Success 201 `{id,expires_at}`.
- POST `/api/notes/:id/meta`: JSON `{token:base64url32bytes}` (peek capability). Success `{header:base64url-exact-header,expires_at:number,remaining:number}`; no ciphertext.
- POST `/api/notes/:id/open`: JSON `{token:base64url32bytes}` (read capability). Success original full binary packet, `Content-Type: application/octet-stream`. Atomic authorization, TTL, decrement and final delete in a single Valkey Lua script. At most N authorized retrievals for N views across all app instances sharing the authoritative primary. An interrupted delivery may consume a retrieval without delivering usable content. No automatic retry of a consuming cache call.
- DELETE `/api/notes/:id`: JSON `{token:base64url32bytes}` (revoke capability), success204.
- GET `/healthz`:200 when cache is available and service ready,503 otherwise; no detailed public diagnostics.
- Errors JSON `{error:code}`. Codes: `unavailable`404 for absent/expired/invalid capability; `invalid_request`400; `too_large`413; `proof_invalid`400; `proof_reused`409; `id_conflict`409; `capacity`503; `rate_limited`429; `forbidden`403. No raw dependency errors.

## Storage and admission

Dedicated Valkey on a Unix socket or loopback. Persistence disabled, bounded maxmemory and noeviction. Each note is one hash including packet, header, remaining, capabilities and absolute expires_at; native expiry always set. Atomic create binds spent challenge and note creation, with bounded challenge lifetime. On capacity reject creation rather than evict live messages. Atomic Lua decisions must not partially spend proofs on errors. Use fixed script source, never inject inputs into Lua.

Challenges are independent random 32-byte values with bounded leases in the shared Valkey primary; there is no signing key. Leases expire after 420s; proof is bound to exact packet bytes; consumed challenge keys expire. Global short-lived counters in Valkey; no user/IP identities. Rate limits for requests, challenge issuance and creation; configurable for integration tests. Per-process semaphore bounds in-flight bodies before buffering, body size and total-time limits; reject overload without queues. Shared cache operations have deadlines. Do not automatically retry consuming operations.

## Browser lifecycle

Svelte text escaping; never render user HTML, file previews, markdown or external URLs. Crypto, KDF and proof solving in dedicated worker. Clear/cancel terminates worker and aborts network; generation IDs and absolute deadlines prevent late results restoring content. Sender and receiver clear sensitive data after5min inactivity, warning30s, real trusted activity only. Decrypted view clears immediately on hidden; waiting receiver may switch tabs to fetch a passphrase. Clear on pagehide. Object URLs are tracked and revoked; no service worker, analytics, remote fonts, browser data store or persistent keys. Theme preference alone may persist.

## Security headers

CSP default-src none; script-src self (wasm-unsafe-eval only if libsodium requires it), style-src self, connect-src self, img-src self data:, worker-src self, base-uri none, form-action none, frame-ancestors none. No inline script or style. nosniff; no-referrer; COOP same-origin; CORP same-origin; frame DENY; strict Permissions-Policy. Static route allowlist (/,/create,/view,/about,/privacy,/terms); nonexistent assets and API routes404, no source exposed. Hashed static assets may be cacheable, HTML/API no-store.
